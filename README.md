Задача 3. Остановка контейнера и проблема проброса портов
Контейнер custom-nginx-demo был остановлен через Ctrl+C. В логах видно корректное завершение worker‑процессов и главного процесса (PID 1) — это подтверждает, что в Docker остановка главного процесса = остановка контейнера.
В контейнере custom-nginx-t2 конфиг nginx был изменён через nano (как более простой редактор): listen 80; → listen 81;. После nginx -s reload сервис стал слушать порт 81 внутри контейнера.
При старом пробросе -p 127.0.0.1:8080:80 страница снаружи стала недоступна — это демонстрирует проблему несоответствия: внутренний порт изменился, а проброс остался прежним.
Для исправления контейнер был остановлен (docker stop) и удалён (docker rm), затем перезапущен с корректным пробросом -p 127.0.0.1:8080:80 (под текущий конфиг образа).
Финальная проверка curl http://127.0.0.1:8080 вернула 200 OK — сервис снова доступен.

## Задача 4. Bind mount между хостом и контейнером

Цель: продемонстрировать двустороннюю синхронизацию файлов между хостом (MacBook Pro) и контейнером.

**Выполненные шаги:**
- В рабочей директории создана папка `mount-test` и файл `hello.txt` со строкой `Hello from host!`.
- Контейнер `bind-test` запущен с привязкой `-v $(pwd)/mount-test:/app`.
- Файл `hello.txt`, созданный на хосте, виден внутри контейнера в папке `/app`.
- Из контейнера создан файл `from-container.txt`, который сразу появился на хосте в папке `mount-test`.

**Вывод:** bind mount обеспечивает общую папку между хостом и контейнером, изменения видны в обе стороны. Это базовый механизм для работы с конфигами, логами и статикой в реальных проектах.

## Задача 5. Docker Compose

Цель: описать и запустить сервис через `docker-compose.yml`.

**Выполненные шаги:**
- Создан файл `docker-compose.yml` с сервисом `web` на основе образа `custom-nginx:1.0.0`.
- Сервис запущен командой `docker compose up -d`.
- Проверка доступности: `curl http://127.0.0.1:8081` вернула `200 OK`.
- Сервис остановлен командой `docker compose down`.

**Примечание:** атрибут `version` в `docker-compose.yml` устарел и игнорируется современными версиями Docker Compose — это не влияет на корректность работы сервиса.
