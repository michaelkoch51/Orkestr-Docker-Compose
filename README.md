## Задача 3. Остановка контейнера и исследование проброса портов

### Остановка процесса PID 1
* Контейнер `custom-nginx-demo` был остановлен в интерактивном режиме с помощью комбинации клавиш `Ctrl + C`. 
* Анализ логов показал последовательное и корректное завершение всех worker-процессов, а затем и главного процесса (`PID 1`). Это на практике подтверждает базовый принцип Docker: **остановка главного процесса (PID 1) всегда приводит к остановке всего контейнера**.

### Изменение портов и симуляция ошибки конфигурации
1. Внутри запущенного контейнера `kochnev-mikhail-sergeevich-custom-nginx-t2` через текстовый редактор `nano` был отредактирован конфигурационный файл Nginx. 
2. Директива конфигурации была изменена: `listen 80;` $\rightarrow$ `listen 81;`.
3. Конфигурация веб-сервера была перечитана внутри контейнера без его перезапуска:
   ```bash
   nginx -s reload
   ```
4. **Результат**: Сервис переключился на порт `81`. При попытке обратиться снаружи по старому пробросу портов (`-p 127.0.0.1:8080:80`) запрос завершился ошибкой, и страница стала недоступна. Данный эксперимент наглядно демонстрирует проблему несоответствия внешнего маппинга внутреннему порту приложения.

### Исправление и перезапуск
Для восстановления доступности контейнер был полностью пересоздан с актуальными параметрами:

```bash
# Остановка и удаление проблемного контейнера
docker stop kochnev-mikhail-sergeevich-custom-nginx-t2
docker rm kochnev-mikhail-sergeevich-custom-nginx-t2

# Перезапуск с корректным маппингом на измененный порт 81
docker run -d --name kochnev-mikhail-sergeevich-custom-nginx-t2 -p 127.0.0.1:8080:81 custom-nginx:1.0.0
```

### Финальная проверка
Выполнена повторная проверка доступности веб-сервера с хоста:
```bash
curl http://127.0.0.1:8080
```
Запрос вернул статус `200 OK`. Сервис снова полностью доступен и корректно отвечает наружу.


## Задача 4. Bind mount между хостом и контейнером

Цель: продемонстрировать двустороннюю синхронизацию файлов между хостом (MacBook Pro) и контейнером.

**Выполненные шаги:**
- В рабочей директории создана папка `mount-test` и файл `hello.txt` со строкой `Hello from host!`.
- Контейнер `bind-test` запущен с привязкой `-v $(pwd)/mount-test:/app`.
- Файл `hello.txt`, созданный на хосте, виден внутри контейнера в папке `/app`.
- Из контейнера создан файл `from-container.txt`, который сразу появился на хосте в папке `mount-test`.

**Вывод:** bind mount обеспечивает общую папку между хостом и контейнером, изменения видны в обе стороны. Это базовый механизм для работы с конфигами, логами и статикой в реальных проектах.

## Задача 5. Docker Compose

Цель: описать и запустить сервис через `docker-compose.yml`.

**Выполненные шаги:**
- Создан файл `docker-compose.yml` с сервисом `web` на основе образа `custom-nginx:1.0.0`.
- Сервис запущен командой `docker compose up -d`.
- Проверка доступности: `curl http://127.0.0.1:8081` вернула `200 OK`.
- Сервис остановлен командой `docker compose down`.
